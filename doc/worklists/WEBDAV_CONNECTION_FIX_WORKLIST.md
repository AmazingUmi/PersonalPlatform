# WebDAV 连接测试修复

## 目标与已知缺口

用户使用坚果云，要求填写连接信息后即可 Test connection，并反馈现有连接测试失败。现有前端仅在连接已保存时显示测试按钮，且未保存编辑会禁用测试；后端测试接口只读取已保存配置。两者均与用户预期不符。已收到具体错误 `Private WebDAV destinations require an operator-configured exact origin allowlist`；主代理在当前生产 Docker 容器内复现 `dav.jianguoyun.com` 解析为 `198.18.0.237`，即保留地址/Fake-IP 范围，且现有 allowlist 为空。连接被网络边界提前拒绝，尚未验证认证信息。主代理以同一生产容器、临时精确 origin allowlist 和虚构凭据调用现有 davRequest，收到坚果云 HTTP 401（TLS 验证保持开启），确认该配置可使请求到达认证层；未读取或验证真实凭据。

## 架构决定

本任务明确修复平台级 Settings 数据备份能力，允许局部修改 `backend/src/core/data-management/`。不修改 App Contract V1、能力模型、迁移或其他 Core 模块。

- `POST /api/core/data/webdav/test` 向后兼容 `{}` 测试已保存连接；新增显式草稿 `{ endpoint, username, password? }`。草稿对象必须同时提供 endpoint 与 username，不接受部分对象或额外字段。
- 草稿连接测试仅验证连接信息，不接受 scope、intervalHours，也不改变配置、计划、备份状态、历史或租约；无需先点击 Save。
- 新配置与更换目的地/用户名时必须提供密码。省略密码时，仅能复用当前登录用户、规范化后 endpoint 相同且 username 精确相同的已保存密码；绝不将保存密码发送到新的目的地或其他账号。
- 显式密码走内存请求，不创建或更新加密密钥文件；读取保存密码才访问已有加密身份。沿用账号有效性检查、输入长度/用户名校验、网络目的地限制和超时限制。
- Connection 表单内始终显示 PixelButton `Test connection`，与 Save 并列。必需连接信息具备后可测试当前输入；测试不依赖保存状态或自动备份间隔。请求期间禁止重复操作，保留输入；成功明确说明已验证连接/目录读取，且测试不会保存配置或开启计划。
- 修改连接字段后清除先前的测试成功提示，防止旧结果被误认为验证了新输入。保存密码占位不回显；测试失败时保留可编辑草稿。
- 针对坚果云加入简短可操作提示（官方 WebDAV 地址、账号、应用密码），以官方资料为准，不要求用户提交密码给代理。

## 传输修复边界

现有请求使用 Basic、Depth: 0 的 PROPFIND、TLS 验证、DNS 校验后固定地址、禁止重定向。当前已定位的失败来自 DNS 的保留/Fake-IP 地址，而非已证实的请求 framing 或认证问题。本轮不进行推测性传输重写。

- 对当前保留/Fake-IP 拦截提供明确诊断，解释服务器 DNS/代理可能返回保留地址，提示操作者检查 DNS/代理或通过既有 `DATA_BACKUP_ALLOWED_ORIGINS` 配置可信的精确 origin。不自动豁免坚果云域名，不放开私网，不忽略证书，不转发凭据到重定向目标。
- 当前部署可追加已确认的 `https://dav.jianguoyun.com` 精确 origin 以适配其 Fake-IP 路由，保留既有 allowlist 项。仅更新本地部署环境/重建必要服务，配置秘密不提交；仍保持证书与凭据验证。先用无真实凭据请求验证网络已到达预期的认证拒绝响应，再由用户使用已知凭据验证真实连通。
- HTTP 401/403、404、405、429、重定向、DNS、TLS、连接/超时可按已需的范围提供适度区分且不泄露远端响应正文、密码、认证头或完整敏感 URL。可针对 401 提示应用密码，但不武断断言密码错误。
- Test connection 的成功只表示已认证并访问 WebDAV 目录，不声明通过文件写入、增量 HEAD 或完整备份验证。本批不自动创建目录、不写探测文件、不新增 DELETE。
- DNS 多地址重试、PROPFIND XML 严格解析或其他广泛传输变更仅在本轮证据证明必需时纳入；记录清单修订原因后再实施。

## 允许范围、执行与非目标

允许：data-management WebDAV 服务/路由/HTTP、对应后端单元与集成测试；前端 dataManagement 客户端、DataManagementPanel 和对应单元/E2E；数据管理说明及本清单。另允许任务相关的本地部署精确 origin 配置修复，不提交本地配置或秘密。

顺序：独立 checkpoint → UI/API 草稿测试 → 证据支持的传输修复与诊断 → 定向测试 → canonical gates → 独立终审 → commit/push/CI。

非目标：数据库迁移、备份格式和增量算法、目录管理、认证协议重设计、全局 SSRF 策略或 App/平台契约改造。
